# DEMO-2 added pilot P10-HANG123: entry-123 isolation matrix (EXPLORATORY)

Registered 2026-10-20 (Task AY), before any P10 run. Approved by Zach
2026-10-20 ("continue"). $0, XPS only, local only. Runners do not read this
file. It adds a pilot; it changes no registered prediction, threshold, arm,
entry set or decision rule of DEMO-2 or of pilots P0-P9.

## Why
Arm A (true default) stopped in the same place twice on the XPS:
multi_turn_long_context_123, turn 0, after the pipeline load returned.
- 841b84e4-0eb8-436d-89f6-c5b558848991 (2026-10-19, after 14 entries; no watchdog).
- 24c1abc0-0613-4890-87b6-3da05350beda (2026-10-20, fresh worker starting at
  123; watchdog fired at 1,800.45 s, exit 86).
py-spy (24c1abc0) shows the main thread in LLMPipeline::generate ->
ContinuousBatchingPipeline::step -> InferRequest::infer -> GPU plugin ->
clEnqueueNDRangeKernel -> igdrcl64.dll -> NtGdiDdDDIWaitForSynchronizationObjectFromCpu.
Analysis: analysis/demo2_pilots/AY/GPU_HANG_ENTRY123.md.

## Design
One entry (DEMO1_LONGCTX_30 index 14 = multi_turn_long_context_123), policy
local_only, gpu_only, RESIDENT, -DebugRawText -MemTelemetry -GpuMemCounters,
-TurnWatchdogS 600 and py-spy. Each cell is its own launch. Each cell moves one
field away from the true default (C0). The explicit SchedulerConfig cells
restate the latency default (prefix caching on, max_num_batched_tokens
18446744073709551615, dynamic_split_fuse on; struct defaults otherwise, which
match the latency config in P0a 597f40a9) and change one field.

| Cell | Change from C0 | launch_h1 flags (on top of the common set) |
|---|---|---|
| C1 | prefix caching off | -Kv default -CompiledReadback -SchedExploratory -SchedPrefixCaching off -SchedMaxBatchedTokens 18446744073709551615 |
| C2 | chunk cap 4096 | -Kv default -CompiledReadback -SchedPrefixCaching on -SchedMaxBatchedTokens 4096 |
| C3 | chunk cap 256 | -Kv default -CompiledReadback -SchedPrefixCaching on -SchedMaxBatchedTokens 256 |
| C4 | KV u4 | -Kv u4 -CompiledReadback |
| C5 | KV f16 | -Kv f16 -CompiledReadback |
| C6 | dynamic_split_fuse off | -Kv default -CompiledReadback -SchedExploratory -SchedPrefixCaching on -SchedMaxBatchedTokens 18446744073709551615 -SchedDynamicSplitFuse off |
| C0 | none (true default; repeat) | -Kv default -RequireTrueDefault |

- C1 and C6 need the harness flags added in Task AY (-SchedExploratory,
  -SchedDynamicSplitFuse; default off). The runner can set
  dynamic_split_fuse, so C6 is kept.
- Order: C1, C2, C3, C4, C5, C6, then C0 last, so a hang costs least (each of
  C1-C6 is a candidate fix; C0 is expected to hang).
- Reboot between cells only after a cell hangs (a hung GPU may leave the
  driver wedged). Every launch starts below 6,900 s uptime.

## Decision rule (fixed now)
- A knob "avoids the hang" if its cell completes turn 0 of entry 123 within
  600 s: local_turn_telemetry.jsonl has a turn-0 row and hang_events.json has
  no turn-0 event.
- A cell that hangs at turn 0 "does not avoid it". A cell that refuses or
  errors before turn 0 is "not tested", with the reason.
- A later-turn hang (turn >= 1) is recorded and reported separately. It does
  not change the turn-0 verdict.
- Each cell's load dump must show the intended single-field change against
  C0's SchedulerConfig and compiled KV. If it does not, the cell is "not
  tested".
- Report: the set of knobs that avoid the hang, plus C0's outcome (a third
  repeat). If C0 completes, the hang is not deterministic, and every C1-C6
  "avoids" verdict is withheld as unconfirmed.
- EXPLORATORY: this pilot feeds no DEMO-2 arm value by itself. Any change to
  arm specs goes through the arm-spec addendum.
