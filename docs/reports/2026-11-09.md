**Cause** (diagnosed on seed 20260901 only; template blob read from the model manifest)
- Ollama's template contains `{{- if and $.Tools $last }}`: tool definitions appear only when the last message is a

  the orginal user question."
- The params blob (stop tokens start_header_id, end_header_id, eot_id) is not involved.
- Evidence, job 98, seed 20260901 (98 invalid calls, all wrong argument names or tools):

  | count | what the model sent | schema |
  |---|---|---|
  | 71 | update_record with an "updates" dict, e.g. `{"record_id": "EV-399", "table": "calendar", "updates": {"time": "14:00"}}` | field and value |

  - lt_openhands_09, call 3: `The ticket T-695 is closed, so no changes are made.\n{"name": "get_record", "parameters": {"record_id":"T-950","table":"tickets"}}`.
    Ollama returned the call as content, and the harness rejected it because the reply was not all JSON.

**Fix** (commit 158464f)
- **Files:** harness/x2_longtask.py, tests/test_longtask.py (7 new tests).
- **Mechanism, 3 lines:** (1) the same tool definitions the API sends are also written into the system prompt, which
  the template renders on every call. (2) If a reply has no native call, the harness searches it for a call object
  naming an offered tool after any prose (method `text_embedded`). (3) It is off by default (`--tool-prompt ollama`),
  so earlier runs and other models are unchanged. The grader and the failure-class rule are unchanged.
