## A1. Preamble: why this amendment exists
- CC-PRECHECK (CC section 1) found that all three sealed XPS limits (553b3a5c, cf3555d5, e4a22dac)
  failed in the uncapped TURN-1 prefill. The probe's turn 2 appends 183 tokens.
- **Retired for the sealed limits:** the MIXED-step "64 x T scratch" explanation. It stays as a
  hypothesis only for agent-like incremental growth (CC-GROW, A9).
- **Competing hypotheses (DERIVED, CC_BL_PREDICTIONS hypotheses):**
  - H-act: a linear prefill working set, a = 96,768 B per token, budget 3.412 GiB.
  - H-quad: a term c x L^2, c = 2.332 B per token^2, that a step cap does not remove.
  - H-grow: grow-by-copy transients or a fixed allocation.
- **The linear prefill mechanism is published** (MOM 2504.12526; Zeng et al. EMNLP'24; HyperGen).
  The paper cites it and claims the consumer-tier consequences, not the mechanism (impact report).
- **Corrections to CC section 1, found in derived/audit/CONFIG_PROVENANCE.md (Task AZ):**
  - The sealed "u8" limit cf3555d5 requested u8 but compiled **i8** (CONFIG_PROVENANCE table:
    "u8 -> i8"). The KV property readback in the run says u8. The compiled type differs.
    - CC's "the 8-bit arm is u8, not i8" is therefore wrong as to the compiled type. The 8-bit arm
      requests u8; what compiles is logged per call (--compiled-readback) and decides the label.

## A4. What counts as a ceiling
- Ceiling = the first allocation or device error. Output correctness is not required (the probe rule
  is "turn 1 completes and turn 2 runs").
- Per-probe child timeout 3,600 s (`--probe-timeout-s 3600`; default 1,800 s unchanged elsewhere).
- A timeout with no allocation or OpenCL error is CENSORED, not a ceiling. The bisection treats it as
  "did not hold" (conservative), and the analysis reports that cell as censored at that n
  (UNRESOLVED above it).
- Failure class from the child record: alloc / CL_OUT_OF_RESOURCES / other exception / paging stall
  (sidecar hard faults with no error) / timeout.
