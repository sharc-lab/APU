## E1: the context window a runtime default assigns by memory tier
**E1.1 Configuration axis.**
- The axis is the local context window and KV precision, with the same checkpoint, the same
  runtime and the same device.
- The device's memory tier decides the default.

**E1.2 Arms** (per device; same model, thinking mode, sampling, system prompt, tool schemas and
instruction protection in every arm):

- **A-default.** Untouched Ollama, with whatever window its VRAM tier assigns: f16 KV and silent
  truncation.
  - The window is VERIFIED, not assumed: every call logs `prompt_eval_count`, and the loaded
    `n_ctx` is logged from the runtime (`ollama ps` / server log).
  - A run whose logged n_ctx is not the tier default is invalid.
- **R (research, "R-full").** num_ctx 40,960 (Qwen3's trained length) and f16 KV.
  - Overflow is refused loudly: the client counts tokens before each call and refuses above
    40,960 - 512.
  - It runs only where a fit check shows it fits. Otherwise R is recorded "does not fit", which is
    a result.
- **X (device-provisioned).** The largest window that the pre-run fit sweep shows fits, with q8_0
  KV and flash attention on.
  - Overflow is detected by the client token count and escalated: loud, and counted.
  - **Fit sweep (PICK)**:
    - candidates 4,096, 8,192, 16,384, 24,576, 32,768 and 40,960;
    - X takes the largest candidate whose single-session load plus one full-window generate
      completes with every layer on the GPU (`ollama ps` 100% GPU) and with >= 1 GiB free system
      memory.
    - Reason: one rule on every device. It refuses CPU offload, which would turn a window win into
      a speed loss.
- **X-q8w (optional, AMD only).** X with q8_0 weights, as a precision lever. It is reported
  separately and never in the E1 family.

**E1.5 Metrics.**
- Cloud escalations, and cache-aware cloud $, needed to hold a FIXED absolute task-success target
  Q_t.
  - Q_t = 0.85 is the endpoint; 0.90 is secondary.
  - The target is fixed in absolute terms, not relative to q (report: a q-tied target is far
    noisier).
- Method:
  - each arm runs local-only with the router passive;
  - ONE shared cloud-only log on the 200 tasks;
  - offline replay with random-order escalation: f(Q) = (Q - p) / (q - p);
  - the DEMO-2 analytic frontier.
- Escalations per 1,000 = 1000 f.
- $ per 1,000 = the replayed per-task cost of the escalated tasks from the cloud log.
- Price:
  - The PF 1 formula per request: cost = (p_in x input + 1.25 x p_in x cache_write + kappa x p_in
    x cache_read + p_out x output) / 1e6.
  - kappa = 0.05 on 5.5-tier models (0.10 elsewhere).
  - The cloud model is Sonnet 5.5 (**PICK**, the report's sheet). List $/MTok: input 2.00, 5-min
    write 2.50, cache read 0.10, output 10.00. These are LITERATURE values from the report and are
    not yet in configs/pricing/anthropic.yaml.
  - The owner adds that row, with its retrieval date, before any E1 cloud call. CostGuard refuses
    an unpriced model.
- Report three sheets:
  - list prices;
  - -50% (batch or negotiated);
  - a cache-hit sweep 55 / 70 / 90 / 95% for any figure extrapolated beyond the logged runs.
- Also reported:
  - wrong-answer rate per arm;
  - silent-failure rate (a wrong answer with no error and no overflow signal).
  - X's overflows are loud BY CONSTRUCTION and are reported as a mechanism, not as a finding.

**E1.6 Tests and claim rule** (per device; fixed sequence within a device; devices in fixed
sequence XPS, then AMD):
1. Exact McNemar on paired local-only pass, X vs A-default, two-sided alpha 0.05.
2. Only if (1) rejects: Delta escalations per 1,000 at Q_t = 0.85, X vs A-default.
   - Paired bootstrap B = 10,000, the same indices in every arm and in the cloud log, seed
     20261023.
   - Two-sided 95% percentile CI. -inf draws are kept, as in PF 3.
3. Only if (2) rejects: the same at Q_t = 0.90.
- Claim: "X needs fewer escalations than the device default to hold 85% task success on <device>"
  only if (1) and (2) reject on that device and the CI excludes 0.
- AMD is tested only if the XPS claim holds.
- X vs R: reported on every device where R fits; secondary; 95% CI.

**E1.8 Pitfalls (each a refusal or a logged check).**
- Ollama's OpenAI-compatible `/v1` endpoint may ignore `num_ctx`. X and R use the native `/api/chat`
  with `options.num_ctx`, and every call's `prompt_eval_count` is checked against the arm's window.
  An X call that shows truncation is invalid.
- llama-server divides `-c` by `-np`. Set `-c` = window x slots, and log the per-slot n_ctx.
- The AMD box's true default may be 40,960 (E1.3).
- Thinking mode is recorded, not varied. It adds tokens.

## E2: KV precision and attention settings, local cost per session
**E2.1 Configuration axis.**
- The axis is KV precision and attention backend: same checkpoint, same window, same device.

**E2.2 Arms** (AMD, qwen3:14b, Rithwik's 40-step sessions, num_ctx 40,960, one session per
machine):
- **R:** f16 KV, flash attention at its default (research config).
- **X0:** f16 KV, flash attention forced on. This is the attribution arm.
- **X1:** q8_0 KV with flash attention.
- Optional: X2 (q4_0 KV), which gets its own non-inferiority test. Also X1-par (2 and 4 slots),
  with `-c` = window x slots; the plateau is about 4 slots.
- **Sessions: 6 per arm** (PICK, the report's number), in a randomized arm order (seed 20261023),
  on identical task sequences.
- Check and record whether the Ollama build turns flash attention on together with quantized KV.
  If it does, X0 is the only way to attribute the gain.

**E2.3 Cross-device replication** (OpenVINO, Qwen3-4B, our harness):
- **T2S** (Rithwik, Oct 26 to Nov 8): i8 (default) vs u4 KV, with 1, 2 and 4 concurrent sessions.
- **XPS** (Zach, after DEMO-2): the same contrast.
- Record GPU-resident vs offloaded layers and peak memory on every host.

**E2.4 Metrics.**
- Wall-clock per session.
- Sessions per machine-day = 1,440 / t_session_min x concurrent sessions.
- Amortized local $ per session = c_dev x t_session_h / p_complete, where:
  - c_dev (active-hour basis) = BOX_USD / (LIFE_Y x 12 x ACTIVE_H_MONTH) + WATTS / 1000 x USD_KWH;
  - c_dev (full utilization) uses LIFE_Y x 8,760 h.
- The cost inputs are INPUTS, with replaceable defaults: $2,000 box, 3 years, 120 W wall,
  $0.16/kWh, 160 active h/month.
  - These defaults give $0.37 per active hour, or $0.095/h at full utilization.
  - Replace them with measured wall power, measured duty cycle and the actual purchase price. Every
    $ figure states which inputs it used.
- Accuracy: non-inferiority of X vs R on the 200 confirmatory short tasks (the E1 pin), paired.
  - The margin is -5 points; one-sided 95% lower bound (Wald, paired) > -0.05.

**E2.5 Tests and claim rule.**
- Session time: Welch t-test on log(session minutes), X1 vs R, two-sided alpha 0.05. The ratio CI
  is the exponentiated difference.
- Claim "X1 runs Y x more sessions per machine at non-inferior accuracy" only if:
  - the ratio CI excludes 1, AND
  - the non-inferiority bound holds.
- Attribution: s = ln(t_R / t_X0) / ln(t_R / t_X1).
  - If s >= 0.5, the label is "attention backend / memory-fit configuration", not "8-bit KV".
  - s is descriptive, with a bootstrap CI over sessions.
- Cross-device: the u4 / i8 sessions-per-day ratio per host with a 95% CI. This is the crossing
  pattern, descriptive.

**E2.6 Predictions** (DERIVED, predictions file E2):
- X1 / R session ratio on the AMD box: 2.85 [2.0, 3.7].
- $ per session: $1.31 -> $0.46 (active-hour basis), or $0.34 -> $0.12 (full utilization).
- Sessions per machine-day: 6.7 -> 19.1.
- Attribution: s >= 0.5 (judgement 65-75%; the report gives 25-35% that KV precision carries it).
- Accuracy: X1 within about 1 point of R. Non-inferiority power is 0.80 at n = 200 with 8%
  discordance, 0.92 at n = 300, and 0.93 at n = 200 with 5% discordance.
- Cross-device u4 / i8 sessions per day:
  - XPS: 1.33 [1.0, 1.5], memory-bound (26,500 / 20,000);
  - T2S: 1.08 [0.9, 1.2], near-null (64 GB never binds).
- Pattern: large on 16 GB and 128 GB, near-null (<= 1.2x) on 64 GB. That pattern is the thesis
  result, more than the 2.85 alone.
- Odds that E2 replicates at least 2x: about 80% (report judgement).
