## 2. Design
- Estimands: L90 (holds with probability 0.9) and L50, per anchor.
- Anchors (XPS, 57% default, plain pipeline as in the CC cells): f16 uncapped, u4 uncapped, f16 cap256.
- Rule: biased-coin up-and-down targeting hold 0.9 (after a fail step down; after a hold step up with
  probability b = 1/9, else stay); step 250; one fresh child per trial (run_resident_limit
  --bcd-start/--bcd-trials/--bcd-seed, new, default off). Block seeds: 1000 x session + 10 x anchor
  index + block. Blocks chain: each block starts at the previous block's next level (Mac state file).
- First start levels: the law L50 (B_BR, compiled k) rounded down to the grid: f16 13,750; u4 24,000;
  f16 cap256 22,000. Ranges: f16 8,000-20,000; u4 12,000-36,000; f16 cap256 12,000-30,000.
- Per session (one boot): 2 blocks per anchor in seeded random order; 8 trials per f16 uncapped
  block, 6 per u4 and f16 cap256 block. At least 3 sessions, at least 30 trials per anchor.
- u4 cap256 (each trial ~10-15 min): no BCD. 20 trials at 63,000 (= 0.9 x 70,000, f8df3847),
  10 per session over 2 sessions; one-sided binomial bound.
- Session hygiene: reboot before each session; log (never change) Defender / McAfee scan state, VPN
  adapters, Windows Search service, Available MB and the active power plan before each session.
- Estimator (tools/stat_cir.py, frozen now with tests): centered isotonic regression of the fail
  rate on level; L90 and L50 by linear interpolation between centered points, censored (not
  extrapolated) outside the observed range. 90% CI: two-stage bootstrap (sessions, then trials within
  session), 2,000 draws, seed 20261026. Reversal count reported. Secondary: logistic model with a
  session random intercept and pre-trial Available MB.
- Exclusion only for a logged perturbing event (scan, update, foreign process, gate refusal). Every
  excluded trial is listed with its reason in AUDIT_LOG.
