## 1. Claims (and claims to avoid)
- C-H1 feasibility map: per tier and configuration, the share of real agent calls that fits locally
  and which ceiling binds (memory, window, TTFT).
- C-H2 predict rather than detect: a closed-form guard before generation removes the default's hard
  failures and silent overruns at a small false-reject cost; a KV-only guard fails where the non-KV
  term says it should.
- C-H3 configuration moves a predicted band, empty on 32 and 64 GB.
- Not claimed: savings, beating RouteLLM, quality, net local-vs-cloud energy, privacy guarantees,
  "first TTFT-aware" or "first length-triggered" routing.

## 3. Definitions
- Local feasibility: memory k*n_ctx + a*min(n_new, c) <= B_eff*(1 - m); window n_ctx <= W; TTFT
  T(n_new | n_ctx) <= SLO. Sessions use the corrected session law (BR_SESS) if Gate B (Nov 8) passes,
  else the measured session ceilings.
- n_new: primary = within-session increase of input_tokens_total, clipped at 0; sensitivity = raw
  newly_append_tokens (no local residency). A decrease larger than one turn is compaction (reset,
  full re-prefill); the share of negative raw differences is reported.
- Sessions are sticky: once escalated, a session stays in the cloud.
- SLO tiers 10 / 20 / 60 s / none; "none" primary for the memory and window hypotheses, 20 s for TTFT.
- Bootstrap: users, then sessions (52 TraceLab users).
- Metrics, in this order, per 1,000 calls and per session: local share of calls and input tokens
  within SLO; hard failures, silent overruns, timeouts; wasted local seconds and Wh; false-admit /
  false-reject vs m; cloud input (cached / uncached) and output tokens; then $/1K calls at three tiers.

## 4. Policies (closed form; all-cloud is only a dashed normalizer)
P0 default-detect (control); P1 config-detect (u4 + chunk-256); P2 ceiling-aware (u4 + chunk-256,
admit iff all three inequalities hold at margin m); P2-KV (a = 0 ablation); P2-U (guard on the default
config); P3 deadline-aware 3-way (unchunked / chunked / cloud); P4 oracle; B-4K (local iff prompt <=
4,000); B-rand (random at P2's cloud share).

## 6. Hypotheses (thresholds as in the plan)
| ID | Prediction | If refuted |
|---|---|---|
| H-NARROW | TraceLab calls with n_ctx <= 40,960: < 25% of calls and < 5% of input tokens | report the larger share |
| H-BAND | P1 - P0 local-feasible share (no SLO) = F(min(L_c, W)) - F(L_u) on every tier; zero on 32 / 64 GB | non-zero 64 GB gain = window or law mis-specified |
| H-CONTRAST | Exgentic feasible share >= 3x TraceLab's on 16 GB | workload finding |
| H-P2 | P2 hard failures + silent overruns <= 10% of P0's, at <= 5 pp local-share loss vs P4 (m = L90) | if failures are cheap, lean on H-SILENT |
| H-KV | unchunked: P2-KV hard failures >= 5x P2's; chunk-256: within +-10% | move P2-KV to the text |
| H-SILENT | if the window probe runs silently past 40,960: P1 overruns silently in every session crossing 40,960 below the memory ceiling; P0 fails loudly; P2 has none | drop H-SILENT, keep the observability table |
| H-RANK | P4 >= P3 >= P2 > P0 on failure waste and local-within-SLO share in >= 90% of sensitivity settings; at 20 s the TTFT roof binds for most calls clearing memory and window | report the count |
- Sensitivity axes: margin m (0; L50->L90; L90 - 15%; 25%), background memory 0 / 2 / 4 GB, residency
  0 / 50 / 90 / 100%, SLO, tier 16 / 32 (DERIVED, hollow) / 64 GB, model (4B; 8B from BR_8B), runtime
  (OpenVINO default vs llama.cpp ubatch 512 if XRT lands), cache hit 55-95% and price tier (dollars
  only), the 74% B_eff point only if Gate A elevates the inversion (no policy result rests on it).
  Pessimistic corner: 16 GB, 4 GB background, 0% residency, +25% error.
