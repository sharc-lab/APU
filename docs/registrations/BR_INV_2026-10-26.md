## 2. Hypotheses (from the plan; ranking is the plan's)
- H1: the advertised device size (0.94 x SharedSystemMemory - 450 MiB: 6.893 / 7.920 / 10.413 GiB)
  drives OpenVINO placement (usm_device vs usm_host, 1.1x shape preallocation below 0.90 x size), so
  a larger share spends a fixed hidden budget sooner.
- H2: a driver / VidMm constraint on large kernel allocations. H3: pinned memory shrinks the pageable
  pool. H4: boot/session variance. H5: minor caches.

## 3. Protocol per boot (Zach sets the slider and reboots between boots)
- Order: boot 1 = 74%, boot 2 = 50%, boot 3 = 74%, boot 4 = 50%. Restore 57% after boot 4.
- The queue stops unless DXGI SharedSystemMemory = SLIDER x ullTotalPhys within 64 MiB.
- Steps, in order, after the reboot and pull:
  1. A19 DXGI record (read-only), GPU_DEVICE_TOTAL_MEM_SIZE check against the formula (+-1 MiB, logged).
  2. Raw allocate-until-failure (tools/inv_alloc_probe.py): USM device, then USM host, then the plugin
     default buffer; 256 MiB chunks, every byte touched, up to 16 GiB; one fresh process per mode.
  3. Fixed-n trials, one fresh child per trial (run_resident_limit --points, plain pipeline as in the
     A25 slider cells): f16 uncapped 4,096 / 6,144 / 8,192 x3 and u4 uncapped 16,384 / 18,432 x3. Order:
     a seeded shuffle per boot and arm (seed 2610260 + boot), arm order seeded too, written to the log
     before the first trial.
  4. Pinned balloons (tools/pinned_balloon.py), each with u4 16,384 and 18,432 once:
     GPU 1 GiB kept resident by a 10 ms gather kernel; CPU 2 GiB VirtualLock. Cells CC-BAL-INV1:*
     with --balloon-floor-credit (the Task BQ rule; the floor stays 7,000 MB).
  5. WPR, boots 1 and 2 only (one capture per arm), if `wpr -profiles` lists GPU: profiles GPU +
     VirtualAllocation + ResidentSet in memory mode around one extra u4 18,432 trial; the .etl stays
     on the XPS (path, size and sha256 logged). If wpr is missing or not elevated, logged and skipped.
- Telemetry on every trial (--trial-telemetry, new, default off): full exception string; per-type
  GPU_MEMORY_STATISTICS and this process's DXGI Budget/CurrentUsage at 10 Hz through the failure;
  time-to-fail; system commit (tools/inv_commit_sidecar.py, GetPerformanceInfo at 20 Hz) and the
  PDH sidecar (1 Hz) run beside each cell.
- Canary and gates as for every CC cell. About 2 h per boot.

- Ceiling differences under 15% are inconclusive.

  in both pairs.
- Mechanism class: H1 if P-INV-1 and P-INV-2 hold; H2 if P-INV-2's H2 branch holds; H3 if P-INV-4
  holds. Gate A (Wed Nov 4) elevates or demotes the inversion (Zach decides).
