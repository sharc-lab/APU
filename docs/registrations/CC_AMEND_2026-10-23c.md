## Model under test
- L* = min(L_mem, L_window, L_TTFT, L_decode), with L_mem = B / (k + a).
  - The capacity equation is MOM's (2504.12526). The paper claims the bounds, the OS-tier term
    and the consumer-tier validation (prior-art report).
- a = 96,768 B per token and B = 3.412 GiB are FITTED to the f16/u4 sealed pair. So the 1.77x is
  circular. Only held-out cells (A20-A25, A29) test the law.

## Source read before registering (A33, openvino.genai 2026.2.1.0 on GitHub)
- **The budget check runs only with an explicit cache size.**
  - The assertion "Requested cache size is larger than available memory size"
    (`budget_in_bytes <= total_available_memory`, cache_orchestrator.hpp normalize_block_counts)
    runs only when cache_size > 0 and num_kv_blocks == 0.
  - The sealed limits used the dynamic cache (plain pipeline, cache_size 0), so they never passed
    through it. Their failures were CL_OUT_OF_RESOURCES during turn-1 prefill (CC-PRECHECK).
  - The "bookkeeping" risk therefore does not apply to the sealed limits. It applies only to
    explicit-cache_size cells (A33, CC-CONC iii/iv).
- **KV block bytes use the compiled input element type.**
  - kv_cache_manager.hpp: m_block_size_in_bytes += shape x `cache_precision.size()`.
  - So KV is not counted at f16. But `element::Type::size()` rounds a sub-byte type up to 1 byte;
    this behaviour is DERIVED, not re-read today. If so, a u4 cache budget is counted at 2x its real
    bytes.
- **Available memory** (utils.cpp get_available_gpu_memory) is
  min(device_total_mem_size - 1.1 x (cl_mem + usm_device [+ usm_host on an iGPU]),
  device_max_alloc_mem_size x number of cache tensors).
  - The usage figures come from GPU_MEMORY_STATISTICS on GenAI's own Core.
  - GenAI never reads the DXGI budget.
- **Client default.** get_latency_oriented_scheduler_config sets max_num_batched_tokens =
  SIZE_MAX and prefix caching on.
  - The other SchedulerConfig fields (dynamic_split_fuse, cache_size 0, num_kv_blocks 0) are the
    struct defaults. They are recorded per cell as "latency default".

## A19. Budget logging (XPS and T2S)

  - QueryVideoMemoryInfo LOCAL and NON_LOCAL (Budget, CurrentUsage, AvailableForReservation,

- **During each generate, 10 Hz in the child** (`--dxgi-trace`): the runtime process's
  QueryVideoMemoryInfo, and the count of RegisterVideoMemoryBudgetChangeNotificationEvent signals.
- **PDH:** the GPU Process / Adapter Memory Shared Usage sidecar (~1 Hz; tools/cc_mem_sidecar.ps1).
- Intel Shared GPU Memory Override value: the display-class registry dump, plus Zach's manual
  record. Driver version: recorded.
- **UNVERIFIED (rehearsal decides):**
  - whether DXGI CurrentUsage counts OpenVINO's OpenCL / Level Zero allocations;
  - that the ctypes vtable slots work on the hosts.
  - The queue records a failed probe and continues without `--dxgi-trace` (logged deviation).
- **Prediction:**
  - T2S SharedSystemMemory = ullTotalPhys - 16,384 MiB (+-256 MiB);
  - XPS SharedSystemMemory = 0.50 x ullTotalPhys (+-256 MiB), or slider x ullTotalPhys if the
    override is set.

## A22. Balloons (no reboot; tools/gpu_balloon.py, a side process)
- **GPU balloon.** It allocates X GiB through OpenVINO's GPU context and touches every byte (device
  tensor + copy_from, or a host tensor written through numpy). It reports its own PDH Shared Usage.
  - The queue runs the cell only if Shared Usage >= 0.9 x X GiB; otherwise NOT_RUN_UNVERIFIED.
  - X in {0, 1, 2} GiB x {f16, u4} uncapped; bisection at a 250-token grid (f16 8,000-18,000; u4
    12,000-30,000).
- **CPU balloon** (numpy, every page written, no GPU): X in {2, 4} GiB at f16.
- **Prediction:**
  - GPU: dL = -4,397 (f16) and -7,767 (u4) tokens per GiB; slope ratio 1.767, band 1.59-1.95.
  - CPU: |dL| < 5%.
- **Registered gate interaction:** the XPS free-memory gate (>= 7,000 MB available) may refuse the
  4 GiB CPU cell (and possibly 2 GiB GPU).
  - A refusal is recorded NOT_RUN (gate). The gate is not loosened (rule 3).
