### Rules (read first, every session, both workspaces)

1. Read this file at session start. Update it at session end, in the same
   commit as the work.
2. No experiment is ever deleted. It can only be marked DONE (with run_id),
   SUPERSEDED (with the replacing id), CHANGED (date + reason, old design kept
   in the row), or PARKED (date + reason + what would revive it).

   (say why) or "changed to fit what we know now" (say what changed).

   and replace VERIFY with a real status.

PARKED, SUPERSEDED, VERIFY.

### Claims the experiments served (2026-10-15, kept for the record)

C1-C5 below are the mechanisms and evidence lines under the thesis above,
not the thesis itself. Their text is unchanged.

- C1 Operating limit: hardware configuration sets how much context an agent
  can serve inside the SLO, and which constraint binds (latency, memory wall,
  context window, toolchain).
- C2 Retention: keeping only needed context moves the limit (23-25x headline; MEASURED (Zach), data location/run_id pending; not yet in this repo; corrected 2026-10-16, Task AS: measured by us, not Rithwik side; SEM-IMPL is built but has no sealed run in this repo; RET-0/RET-1 are blocked here).
- C3 Routing and cost: which routing triggers fire, and what the cloud bill
  is, depends on the device configuration.
- C4 Budget-quality: hardware configuration sets the test-time compute budget
  per turn, and that budget decides local quality.
- C5 Space shape: the configuration space differs in shape across platforms
  (axes appear, flip, collapse), not just in values. NPU (2026-10-12, NATSTOP N3): the toolchain sets the cap; output validity sets what is usable. NPU (2026-10-13): the NPU's usable envelope may depend on the model export format; for the Qwen3-4B INT4_SYM group size 128 IR on openvino-genai 2026.2.1 there is none so far (N3, B3). Tested by NPU-FORMAT-F1 and NPU-1-CW.
- [private] [private]: DSE / replay that predicts configurations.
- Unifying thesis (superseded 2026-10-15 by docs/THESIS.md, kept for the
  record) (2026-10-12, docs/DEMO1_DESIGN.md): every cloud turn buys
  capability, latency or context. Hardware configuration changes only the
  latency purchase, for turns whose n_ctx lies between configurations'
  envelopes (envelope x trajectory). C1 sets the edge; C2 moves trajectories
  relative to the edge; C3 cost = trajectory mass beyond the edge x price; C4
  is the time side of the envelope; C5 is where the edges sit and their slope
  per platform.
